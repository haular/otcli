# otcli 1.0.0 Publication Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task.

**Goal:** Get `otcli` ready for public PyPI publication as version 1.0.0 — fix the persisted-paths bug, eliminate import-time side-effects, replace the global mutable `config` singleton with a typed `ClientConfig` injected through services, modernize the CLI/UX layer, trim runtime dependencies, and add CI.

**Architecture:** Layered package (`domain/` pure logic + types; `infrastructure/` external I/O — Docker via subprocess, TOML via stdlib `tomllib` + `tomli-w`, HTTP via `curl`; `services/` orchestration receiving an injected `ClientConfig`; `cli/` Typer entrypoint that builds the config and passes it down). All persisted state lives in `~/.otcli_config/clientes/<name>.toml` with a sectioned schema validated on load. Backwards compatibility with pre-1.0 configs is **not supported** — old configs cause a clear failure with reconfiguration instructions.

**Tech Stack:** Python 3.12+, Typer (commands), questionary (interactive prompts), dataclasses (config schema), `tomllib` (read) + `tomli-w` (write), `subprocess` (Docker + curl), pytest + ruff + mypy, GitHub Actions CI, `uv` build.

**Branching strategy:** One branch + one PR per phase. Branch naming: `phase-N-<short-name>`. Each PR is self-contained and mergeable on its own; later phases assume earlier ones are merged into `main`.

**Repository:** https://github.com/haular/otcli (private during alpha/beta).

---

## Phases

1. **Phase 1** — Hotfix: stop persisting derived runtime paths in client TOMLs.
2. **Phase 2** — Eliminate import-time side effects; introduce `paths.Settings`.
3. **Phase 3** — Sync README, drop outdated `GEMINI.md`, add `CHANGELOG.md`.
4. **Phase 4** — `pyproject.toml` ready for publication; `py.typed` marker; public API exports.
5. **Phase 5** — GitHub Actions CI + PyPI publish workflow.
6. **Phase 6** — Add `environment` field to interactive flow; remove `workdir.py` `os.chdir` side-effect.
7. **Phase 7** — `ClientConfig` dataclass + dependency injection (BREAKING).
8. **Phase 8** — CLI/UX cleanup with `questionary`; new `config` and `backups` subcommands.
9. **Phase 9** — Trim runtime deps: drop `docker` SDK and `toml`.

Each phase produces an independently-mergeable branch and PR. The full content of every task with code, tests, expected outputs, and commit messages is documented inline below.
